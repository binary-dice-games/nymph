# nymph — Agent Connectors: Plan

Design: [DESIGN.md](DESIGN.md). Each step is a reviewable deliverable; the
next starts after its tests pass. Native tests go in `tests/` with
`nymph_add_test(<name> <sources>)`; web tests extend `web/tests/node/` and
`web/tests/browser/` (Playwright with the preinstalled Chromium, skipped
with 77 when Playwright is missing), serve the built site from a local
server on port 0, and wait on conditions, never fixed sleeps. Nothing in
this project calls a model API. A `CHANGELOG.md` entry is added with each
user-visible step (4 to 9).

## 1. Risk check: what the browsers and agents really do

**Goal:** every *unverified* fact in DESIGN.md is checked, and the design
is corrected where one is false, before anything is built.

**Deliverables:** throwaway pages and scripts in the scratch build (not
committed), and the results written into this step's **Result**, item by
item:

1. `ws://127.0.0.1:<port>` from an https page on `*.github.io`: Chrome
   (Local Network Access prompt for WebSockets: wording, once or per site),
   Firefox, Safari (mixed content).
2. WebMCP: which Chrome version and flag or origin trial exposes
   `navigator.modelContext`; the registration API's exact shape; whether
   Gemini in Chrome or Claude in Chrome calls a page's tools.
3. `notifications/tools/list_changed` from a stdio server mid-session: do
   Claude Code, Cursor and Gemini CLI re-read `tools/list`? Decides
   whether `web_app_call` is needed (DESIGN.md section 7.2).
4. MCP Apps hosts (Claude Desktop, Claude Code, Cursor): the request an App
   uses to open a link, and whether the host asks the user first.
5. Clipboard write and download from inside the confirmation dialog's
   Allow handler after an `await` (the registry's path).

**Tests:** none committed; each item records what was run, on which
version, and the outcome.


**Result (partly done, Chromium only):**
1. *Loopback WebSocket*: in Chromium 153 through Playwright, a page served
   as `https://binary-dice-games.github.io/nymph/` (the request
   intercepted) cannot open `ws://127.0.0.1:<port>`:
   `net::ERR_BLOCKED_BY_LOCAL_NETWORK_ACCESS_CHECKS` (and `fetch` is refused:
   "Permission was denied for this request to access the loopback address
   space"). With the `local-network-access` permission granted to the
   origin, the socket opens and the server sees `Origin:
   https://binary-dice-games.github.io`. So Chrome asks the user once per
   site; the Connect dialog's error says to allow it. Firefox and Safari
   not tried.
2. *WebMCP*: `navigator.modelContext` is absent in Chromium 153, also with
   `--enable-features=WebMCP,WebMCPTesting` and
   `--enable-experimental-web-platform-features`. `webmcp.js` follows the
   draft (both `registerTool` and `provideContext`) and is tested against a
   stub; no real browser agent tried.
3. *`tools/list_changed`* in Claude Code, Cursor and Gemini CLI: not
   checked (needs signed-in clients). `web_app_call` is therefore always
   listed.
4. *MCP Apps open-link*: not checked in a real host; the App shows the
   link when the host refuses.
5. *Clipboard and download after the confirmation's Allow*: the download
   works in Chromium (tested); the clipboard after an `await` not tried.

## 2. Registry: the agent tool list, origins, change groups

**Goal:** the registry gives every connector one stable, guided tool list
and owns origins, confirmation and change groups.

**Deliverables:** `commands.js`: `agent` field, `agentTools()`,
`callAgent(name, args, connector)` (connectors `webmcp` and
`mcp:<name>` only), guidance for unavailable commands, "Allow for this
session", change groups (DESIGN.md section 4.4: open, reopen after a user
change, idle and disconnect timeouts, refusal for a second connector).
`main.js`: `agent: false` on the eight shell-only commands,
`app_read_guide`, `app_example_source`, `document_begin_change`,
`document_end_change`. `web/app/editor-tools.json` (generated by
`web/tools/dump-editor-tools.mjs` from the editor module, committed).
`docs/agent-web-app.md`, copied to `agent/web-app.md` by `nymph-site`.
`device.js`: `agents` from `config.json`; `NYMPH_AGENT_CONNECTORS`.

**Tests:** Node: `editor-tools.json` equals the editor module's
`toolDefinitions()`; every `agentTools()` schema is valid JSON Schema;
`agent/web-app.md` names only `agentTools()` commands. Browser:
`agentTools()` is the same in View and Edit, has the editor tools on
desktop and none on an emulated phone, and no `agent: false` command;
`editor_set_fields` through `callAgent` in View mode returns the "call
app_set_mode" guidance; `callAgent` with connector `user` throws; an
`external` command with "Allow for this session" ticked runs a second
time without a dialog and asks again after the document closes;
`app_read_guide("web-app")` returns the guide and `../index.html` is
refused; two writes inside a change group are one undo step in Edit
mode; a second connector's `document_begin_change` is refused while the
first's is open; a group closes after the idle timeout (shortened by a
test option).


**Result (done):** as planned, plus `Commands.hooks` (editor groups, snapshots) and `onAgentCall`, which the activity list uses. A test-only option shortens the group idle time (`commands.groupIdleMs`). The guide is `docs/agent-web-app.md`, served as `agent/web-app.md`. `NYMPH_AGENT_CONNECTORS` reaches the site script comma-separated (a CMake list would split the custom command's argument). Tests in `web/tests/browser/agents.mjs` (ctest `nymph_web_agents_browser`); the JSON-Schema check is structural (type, required names a property).
## 3. `editor_model`: another origin ends the group

**Goal:** a user's change during an agent's change group is never undone
with it.

**Deliverables:** `editor_model::commit` (and every change through it)
ends the open group when the change's origin differs from the group's;
`spec/15_web_app/DESIGN.md` section 5.1 notes it.

**Tests** (`test_editor_attribution`): agent group, two agent commits, a
user commit, `begin_group` again and an agent commit: three undo entries,
labelled agent, user, agent; one undo restores only the last agent
change; a commit with the group's own origin still joins it; the existing
attribution tests pass.


**Result (done):** `editor_model::apply()` ends the group when `origin_` differs from the group's. The three existing group tests now set the agent's origin before committing, as every caller does (`call_editor_tool`, the web module). `test_editor_attribution`: two new tests.
## 4. Agents panel and activity

**Goal:** the user sees every agent and every change it made, and undoes
any of them, in Edit and View mode.

**Deliverables:** `agents/panel.js` (DESIGN.md section 5: Agents button
and `Ctrl+Shift+A`, connections, Connect an agent dialog with the code
field, the WebMCP switch, Stop, bottom sheet on phones), `agents/activity.js`
(entries, snapshots, Undo rules); dock content in `index.html` and
`app.css`; `docs/web-app.md` section on agents.

**Tests** (browser, the test connector): the Agents button is absent when
`config.json` enables no connector; the panel opens by itself on an
agent's first tool call; a group is one activity entry with its tools on
expand; Undo of the last entry in Edit mode uses the editor's undo; in
View mode Undo restores the snapshot; an entry changed since asks before
restoring; Stop ends the group and refuses the connector's next write;
read calls are not listed, an allowed `external` call is; a hostile label
(`<img src=x onerror=…>`) shows as text; on an emulated phone the panel
is a sheet without Connect; an axe-core scan of the open panel has no
serious violations; no request leaves the local server.


**Result (done):** `web/app/app/agents/panel.js`, `activity.js`. Undo in Edit mode uses the editor's undo when its version has not moved since the entry's last write (no new export was needed). An entry whose change replaced the document (`app_new_document`) has no Undo. The axe-core scan was not run (axe is not available offline here). Found and fixed: the Connect dialog's button closed the dialog with the word "submit" before the form's submit handler ran (the shell's "Open from URL" dialog builds its button the same way and may have the same problem).
## 5. WebMCP

**Goal:** a browser agent that supports WebMCP uses the app's tools on the
open chart.

**Deliverables:** `agents/webmcp.js` (DESIGN.md section 7.1, in the API
shape step 1 recorded): registration on the document screen, removal on
the start screen, the panel's switch, connections and activity entries.

**Tests** (browser, a stubbed `navigator.modelContext` recording
registrations): tools are registered when a document opens and removed
when it closes; a stubbed agent call to `editor_set_fields` changes the
chart with origin `agent:webmcp` and appears in the activity list; an
`external` call waits for the dialog; the switch off unregisters; without
`navigator.modelContext` nothing happens. By hand: a Chrome that has
WebMCP, if step 1 found one.


**Result (done, against a stub):** `agents/webmcp.js`; tested with a stubbed `navigator.modelContext` (`registerTool`). No browser here has WebMCP (step 1).
## 6. Native transport: loopback TCP and WebSocket

**Goal:** `nymph` can serve a WebSocket on 127.0.0.1 on every platform.

**Deliverables:** `src/ipc/loopback.hpp/.cpp` (listener on 127.0.0.1 port
0, accept, read, write, close; `#if defined(_WIN32)` guards as
`local_socket`); `src/mcp/sha1.*`; `src/mcp/websocket.hpp/.cpp` (DESIGN.md
section 7.2: upgrade with `Host` and `Origin` checks, frames, 16 MB limit,
ping, close); built into `nymph_mcp` only.

**Tests** (`test_websocket`): SHA-1 test vectors; the RFC 6455 example
key gives the example accept value; a test client sends masked,
fragmented and control frames and gets the messages back in order; an
unmasked client frame, an oversized message, a bad upgrade and a wrong
`Host` or `Origin` are refused and closed; close is answered; all threads
join on destruction. CI builds and runs it on Linux, macOS, MSVC and
MSYS2.


**Result (done, Linux):** `local_stream` gained `read_some()`; the loopback listener lives in `local_socket.cpp` beside the file socket so Winsock setup is shared (`loopback.hpp` declares it); a listener that stops closes its socket from the accepting thread. `websocket` owns its stream from the start (`accept_upgrade()`), so a connection still in its handshake can be shut down. `test_websocket` (10 tests). MSVC, MSYS2 and macOS not built here.
## 7. `nymph mcp` web bridge

**Goal:** an agent that runs `nymph mcp` pairs with the open web app and
uses its tools.

**Deliverables:** `src/mcp/web_bridge.hpp/.cpp` (pairing codes, resume
tokens, allowed origins with `NYMPH_WEB_APP_ORIGINS`, page links, calls
with a 5-minute wait); `web_app_pair` and `web_app_call` (in
`web_bridge.cpp`); `editor_bridge` listing paired pages (`web:<name>`, focus);
the page's `document_*` / `app_*` tools added to `nymph mcp`'s list while
paired, with `tools.listChanged: true` and
`notifications/tools/list_changed`; `json_rpc` writer mutex; the client name as
`_meta["nymph/origin"]`; the server instructions,
`claude/skill/nymph/SKILL.md` and `docs/agent-guide.md` say when to call
`web_app_pair`.

**Tests** (`test_web_bridge`, a C++ test page client over the
WebSocket): `web_app_pair` returns a code and a link with the port; the
page pairs and gets a resume token; a reused code, a wrong code and three
wrong codes (listener closed) are refused; a reconnect with the resume
token works without a code; the client's `tools/list` gains the page's
`document_set_source` after pairing and a `list_changed` notification is
written to the client's stream; the client's `document_set_source`
reaches the page with `_meta["nymph/origin"]` and its result comes back;
`editor_set_fields` with no `editor` goes to the page focused last,
`editor: "web:flow.yaml"` to that page, and a native editor still works
beside it; a page that does not answer fails the call after the wait
(shortened by a test option); a closed page fails waiting calls and drops
its tools; `web_app_call` reaches any tool of the page; without
pairing the session's tool list and behaviour equal today's (existing
`test_mcp*` tests pass).


**Result (done):** `src/mcp/web_bridge.*`; the page tools reach the list through `tool_registry::set_dynamic()`; `run_mcp` writes responses and notifications under one mutex. `web_app_call` is always listed (step 1 could not check `list_changed`), and no `web_app_link` tool was built (step 9). The existing tool-list tests count the two new tools. `test_web_bridge` (13 tests, 30 runs in a row without a failure).
## 8. Page side of the bridge

**Goal:** the user connects Claude Code, Cursor or Gemini CLI to the open
app with a code or a link.

**Deliverables:** `agents/bridge.js` (DESIGN.md section 7.2: the code
field and the `#pair=` route, the page as MCP server over the WebSocket
with its `instructions`, `callAgent(…, "mcp:<client>")`, resume through
`sessionStorage`, `nymph/focus`, Disconnect, the browser's refusal
explained); CSP `connect-src` loopback WebSockets; `docs/claude.md`,
`docs/cursor.md`, new `docs/gemini-cli.md` (pairing, per client).

**Tests:** browser, with a native `nymph` from the build when the web job
has one (else skipped with 77): a fake MCP client drives `nymph mcp` on
stdin and calls `web_app_pair`; the page opens `#pair=<code>`; after
`app_set_mode` edit, the client's `editor_set_fields` changes the title
on the page and the activity list shows `mcp:test-client` with Undo; a
reload of the tab reconnects by resume token; a page from another origin
is refused; a wrong code shows the field's error. By hand: Claude Code,
Cursor and Gemini CLI paired on the deployed site in Chrome and Firefox
(Safari's result from step 1 noted in the docs).


**Result (done):** `agents/bridge.js`, the `#pair=` route (the code leaves the address at once), resume tokens per port in `sessionStorage`. The end-to-end tests run a native `nymph mcp` given as `NYMPH_NATIVE_EXE` (third argument of `agents.mjs`) and are skipped without it; here they ran with `build/app/nymph`: pairing by link, editing in Edit mode, Undo, reconnecting after a reload, the Connect dialog with a wrong and a right code, an origin `nymph mcp` refuses. Not tried with a real Claude Code, Cursor or Gemini CLI.
## 9. "Open in the web app" from the MCP App

**Goal:** a chart shown in the agent's chat opens in the app, paired with
the same agent, in one click.

**Deliverables:** the menu item in `claude/app/` (DESIGN.md section 7.3),
calling `web_app_pair`, building the `#y=…&pair=…` link in the App, and
the host's `ui/open-link` request, or showing the link where the host has
none; `docs/claude.md`.

**Tests:** the MCP App's existing harness (stand-in host, 06 section 9):
the button calls `web_app_pair` and asks the host to open a link that
holds the shown source and the code; with no open-link support it copies the link. By
hand: Claude Desktop opens the app on the chart, and the agent in the chat
then edits it there.


**Result (done, stand-in host):** the button in `claude/app/`, tested in `web/tests/browser/run.mjs` with the stand-in host answering `web_app_pair` and `ui/open-link`, and refusing it. Claude Desktop not tried.
## 10. Documentation and status

**Goal:** users and the owner can find, use and configure the connectors.

**Deliverables:** `README.md` (one line: connect your agent to the web
app); `docs/web-app.md` (agents, pairing, privacy: the app never sees a
key; the owner's `NYMPH_AGENT_CONNECTORS`); `CHANGELOG.md`;
`spec/INDEX.md` status.

**Tests:** the docs' links resolve; a deploy from `main` serves the Agents
button and `config.json` with the `agents` section.


**Result (done):** README, `docs/web-app.md` (Agents), `docs/claude.md`, `docs/cursor.md`, `docs/gemini-cli.md`, `docs/cli.md`, `docs/agent-guide.md`, the skill text (and the plugins' copies, by `nymph-plugin-sync`), CHANGELOG, `spec/INDEX.md`. The first deploy is not done.
## Completion Criteria

- Every test above passes in CI (native on Linux, macOS, MSVC and MSYS2;
  web tests in the web job and `pages.yml`); the viewer and editor modules
  and their APIs unchanged and within their size budgets; `nymph mcp`
  without pairing unchanged.
- On the deployed site, by hand: Claude Code, Cursor and Gemini CLI paired
  through `nymph mcp` create and edit a chart in View and Edit mode in
  Chrome and Firefox, with a download confirmed and a change undone from
  the activity list; "Open in the web app" from Claude Desktop; WebMCP
  where a browser offers it.
- Every agent change is attributed, listed and undoable, and every
  `external` action from an agent was confirmed; the app holds no
  credential and calls no model API; no loopback socket is opened for a
  user who never pairs.
- `spec/INDEX.md`, `README.md`, `docs/web-app.md`, the client docs and
  `CHANGELOG.md` describe what was built.
